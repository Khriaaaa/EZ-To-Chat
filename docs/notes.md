# 工程笔记

README 之外的实测记录。都是真跑出来的结论，不是推测 —— 留着是为了下次别重复踩。

## 1. 采集层：UIA 到底给了什么

（微信 4.1.15.13 / winapp-cli 0.7.1，Windows 10 虚机）

### 能读的

- 会话列表：`ui inspect session_list -a Weixin -d 3`
  子项 `session_item_<联系人>`，`name` = 联系人 + 最后一条预览 + 时间
  - 这条同时是**只读监测「没打开的那些会话」**的入口：不点、不切会话就能拿到它的最新一条
    预览（`collector/wx_collector.py` 的 `session_list_rows`，落库带 `src=session_list`）
- 聊天消息：`ui inspect chat_message_list -a Weixin -d 12 --json`
  - `mmui::ChatTextItemView` → 真消息，`name` 是正文
  - `mmui::ChatItemView` → 时间分隔条，`name` 形如 `昨天 08:36`
  - 每条带 `x/y/width/height` + `selector`，顺序即时间顺序

### 读不到的（硬缺口）

**UIA 不给发送者。** 气泡 `name` 只有正文；所有 ListItem 的 `BoundingRectangle`
都是整列表宽度，左右对齐不体现在 UIA 边界里；挖到 `-d 12` 没子元素，
`get-property` 的 19 个属性里没有一项能区分方向。

于是发送者归属只能靠两条间接证据：

1. **引用气泡**（优先）：UIA 直读文字，比像素稳。一对一聊天里
   「引用 对方昵称 的消息 → 这条是我发的」，「引用 我自己的消息 → 这条是对方发的」
2. **截图条带**（没有引用时）：按 `ChatItemView` 给出的 `y/height` 裁出该行，
   统计非背景像素偏左还是偏右。要先把窗口原点（UIA 屏幕坐标）和气泡区左右边界
   从当前界面上现取 —— 写死坐标的版本在窗口被拉宽之后会把「我发的」判成对方发的，
   再经改写路径把历史行也改错

### 工具坑

1. **QGA 起的进程在 session 0**，读不到 session 1 的窗口。所有 UIA 操作必须
   `PsExec64 -accepteula -nobanner -i 1 -d powershell.exe ...` 注入交互会话
2. **.ps1 送过去要 UTF-8 BOM**。PS 5.1 对无 BOM 的 .ps1 按 ANSI 读，
   中文选择器（`session_item_某某`）会变乱码砸坏引号。写文件时前置 `EF BB BF`
3. **别把长脚本塞进 `-EncodedCommand`**。外层 QGA 在某个长度阈值上直接报
   `guest-exec: Failed to execute child process (Permission denied)`，
   跟内容无关、跟长度有关。落地成文件用 `-File` 最稳
4. **推大脚本别走 ps1run**：它把整个脚本 base64 塞进一条 QGA 命令行，脚本超过 ~8KB 被
   `guest-exec: Failed to execute helper program` 拒掉。改用 `ga.py put`（分片走
   guest-file-write），推完按虚机上的实际文件大小校验
5. `ui inspect` / `ui click` 等**必须带 `-a Weixin`**，漏了报 `missing_app`
6. 窗口 HWND 会变，脚本里先 `list-windows` 解析出来再用 `-w`；
   有多个窗口时别让它「自动选最大的那个」—— 选错窗口就没有 `chat_message_list`
7. `ui invoke` 对 `session_item_*` 返回成功但**界面不切**；`focus` + `click` 才真打开。
   判据是截图字节数变了，不是返回值

## 2. 填入通道：为什么必须绕这么一圈

链路：写文本到虚机 → 以交互用户跑的计划任务设置剪贴板并保活 → 按窗口矩形算输入框坐标 →
QMP 点一下 → QMP `ctrl v`。全程 6 秒左右，**不按回车**。

三条都是实测：

1. **从 Windows 进程里用 SendInput / keybd_event 注入的键盘事件，微信一律不收**。
   `SendInput` 返回 2（事件都进栈了）、前台窗口也确认是微信，输入框里一个字符都不出现。
   鼠标 `mouse_event` 同样不可靠
2. **只有 QMP 注进虚拟硬件的事件才收**。QEMU 的按键事件只能给 qcode，出不了中文，
   所以中文必须借剪贴板
3. **剪贴板得由虚机内的进程设置**。容器直接改不了；用 guest-agent 以 SYSTEM 身份跑也没用
   （session 0 的剪贴板和 session 1 不是一个）。设完不能马上退出 —— owner 进程一退
   剪贴板就空，要保活到粘贴完成

计划任务用 `schtasks /create /tn <名字> /xml` 导入 XML 建（principal 写用户 SID +
`InteractiveToken` + `HighestAvailable`），**不需要密码**，比 `schtasks /create /ru ... /rp` 干净。

**填入默认关闭。** 这个项目的主张是「只给建议」，填入只是留个口子：
环境变量或 `store/.allow_fill` 才开。

## 3. 踩过的坑（都已修）

- **QGA 读文件会在 guest 侧漏句柄**，那个路径之后永久写不进去（“文件正被另一进程使用”）。
  症状是每轮留一个 `.tmp` 而正式文件停在旧内容，而且 `Move-Item` 没加 `-ErrorAction Stop`
  时**不抛异常**，日志照样打 `ok`。修法：每轮写唯一文件名 + 一个 `shot.name` 指针
- **一轮采集只落一个 `round.json`**（原子写，里面装 chat/title/sessions/window/shot 五份）。
  老版本是五个文件各写各的、外侧再逐个拉：访客每 2 秒重写一遍而一次拉取要好几秒，
  于是会拿到「chat 属于第 N 轮、shot 属于第 N+2 轮」的拼图。sender 判错、消息挂错会话都从这来
- **采集循环必须单实例**。锁文件要**原子独占创建**（`CreateNew`），
  老写法「读 → 写 PID → 睡一会儿 → 读回比对」在两个进程同时启动时会双双认定锁是自己的；
  另外锁文件里的 PID 已经死了要能自动清掉，否则一次 kill 之后采集再也起不来
- **消息身份不能把 sender 算进哈希**。同一条消息重看一遍时发送方可能从 unknown 被改判，
  哈希一变就成了新行 —— 同一句话会入库两遍。指纹只取 `session + text + 第几次出现`
- **截图这一轮什么都没量到（左右都空）时不要入库**。那是抓图失败或窗口被盖，
  存下来就是一条 sender 说不清、位置也说不清的废行
- **消息身份用「序列对齐」而不是纯指纹**。UIA 不给每句话稳定 id，老逻辑拿
  (会话, 文本, 第几次出现) 当身份：同一句话隔一阵再发、前一次已滚出视野时两次编号都是 1，
  新的那条就被当成「已见」静默丢掉。现在把窗口尾部和库尾对齐，接点之后的一律算新；
  对不齐时退回指纹判重，且必须满足「这一屏确实是该会话的延续」才写库
- **库里「读整库 → 判新 → 追加/改 sender」那一段要加文件锁**：面板自检和别的入口
  是两个进程，各拉各的；本地暂存文件也要按 PID 分名，否则同一个 `.part` 会被两边抢。
  拿不到锁时**必须让这一轮失败**，不能静默降级成无锁执行
- **改历史行要写临时文件再原子替换**。直接 `open(w)` 会先把文件截成 0 再逐行写，
  进程中途被杀就只剩前 N 行 —— 丢的是文件尾部的历史
- **滚动步长要小**：每轮往下拨一格就够。一次跳一个视口，中间的消息会永久漏掉
- **带推理的模型 `max_tokens` 给小了，`content` 会是空字符串**（不是报错），
  看着像模型没回话
- **候选链的总预算要自己管**。链上每个 provider 单发超时 120s，链长 4 个时最坏 480s，
  比调用方的 subprocess 超时还长 —— generate 会在还没轮到备用 provider 时就被杀掉，
  然后原样重试。现在每个候选只分到「总预算剩余」，整轮一定在预算内结束
- **失败重试要按会话记账**。把一批新消息的指纹存成一个列表、前一个会话成功就清空，
  后面那个会话失败时已经无指纹可撤 —— 它的消息被永久记成「已见」，
  不生成、不报错、面板也看不出来。现在按会话分别记，失败的只撤自己那批

## 4. 面板版式

从上到下：标题栏「回复建议 + 更新时间 · N 条候选」→ **当前会话条**（头像 + 名字 +
采集/自检状态）→ 状态提示行 → **对方最近说**（引用对方原话）→ **对话参考**
（紧张度 N/9 + 进度条、建议、可能意图、可能需要）→ 候选卡片（推荐回复高亮 +
百分比 + 风格标签 + 填入/复制）→ 页脚「AI 生成内容仅供参考，请自行判断」。

参考实现里的「当前会话」条原本是聊天窗口的输入工具栏（麦克风/图片/附件那些图标）。
网页侧栏没有那些功能，那一条就只放真信息：会话名 + 采集状态 + 自检时间，
**没有摆装饰性图标**。

`tension`（紧张度）是模型给的弱字段：prompt 要求 1-9，`generate.py` 夹到 1-9、
缺了默认 5 —— 它不该让整轮生成失败。
